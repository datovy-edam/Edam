# ADR-0008 — Catalog wire contract: migrate service clients/UI onto `Contracts` value-record shapes

- **Status:** Accepted — migration direction (2026-09-15)
- **Context:** With the Npgsql `Edam.Data.Catalog.Contracts.ICatalogStore` provider ready (ADR-0007, BL-7.2), retiring the EF `Edam.Data.CatalogDb` layer requires re-pointing the catalog **service endpoints** from `CatalogDb`'s EF-backed instances onto the `ICatalogStore` provider. The catalog `Edam.Data.CatalogModel` still defines **rich EF entity shapes** (`ContainerInfo`, `ItemInfo`, `ItemDataInfo` with many properties and navigation collections), while `Edam.Data.Catalog.Contracts` defines **lean value records** (`ContainerInfo(Guid Id, string ContainerId, string Description, ContainerType ContainerType, string ContainerUri, string ContentType)`, `ItemInfo(Guid Id, Guid ContainerId, string FullPath, string Name, string? Description, ItemType Type, DateTimeOffset CreatedDate, DateTimeOffset UpdatedDate)`, `ItemDataInfo(...)`). The service endpoints return the Model shapes and the HTTP clients (`CatalogClient`) + WinUI (`Edam.UI.CatalogExplorer`) deserialize those responses, so switching the endpoints onto the `ICatalogStore` changes the JSON wire contract and the client-side deserialization target types. `ContainerType` also exists in **two** namespaces (Model vs Contracts).
- **Decision:** **Migrate the service clients and UI onto the `Edam.Data.Catalog.Contracts` value-record shapes** as the single canonical wire/domain contract. The catalog service endpoints return Contracts value records (via the Npgsql `ICatalogStore`), the HTTP clients (`CatalogClient`, `ClientCatalog*`, `CatalogFileSystemClient`, `CatalogBaseClient`) deserialize into Contracts records, and the WinUI consumers (`Edam.UI.CatalogExplorer`, Testing) bind to Contracts records. The `CatalogModel` rich EF entities fall out of the active path and are retired together with `CatalogDb`. `ContainerInfo`/`ItemInfo`/`ItemDataInfo`/`ContainerType` in code and serialized payloads resolve to the Contracts definitions only.
- **Update (2026-09-18):** the Contracts-native client is now **`CatalogHttpClient`** (+ `CatalogHttpContainer`/`CatalogHttpItem`/`CatalogHttpItemData`), which is what the WinUI/Testing consumers bind to; the Model HTTP client (`CatalogClient`, `ClientCatalog*`, `CatalogInstance` + its dead `WebApp/` helper) was **deleted**, and `CatalogFileSystemClient` was renamed **`FolderCatalogClient`** and moved into the `Edam.Data.CatalogServiceClient` namespace. `CatalogBaseClient` remains the Model client base (the WinUI helper still uses its `SessionId`). The folder-as-catalog capability is a live provider, not retired code.
- **Consequences:**
  - **Breaking, but deliberate:** the HTTP payloads and client deserialization target types change; clients/UI must be compiled and run against the new shapes. The agent sandbox DOES have internet/NuGet (it can restore EF/ASP.NET and compile-verify the catalog graph online); its only Docker-related boundary is the engine **pipe (`Access is denied`)**, so it cannot start the Postgres container — the **runtime** verification runs against the live Postgres the user starts (`docker compose up -d --pull always`). Compile is verified by the agent; runtime is verified by the user.
  - Single set of records (ADR-0006 purity): one `ContainerInfo`/`ItemInfo`/`ContainerType` across service, clients, and UI.
  - Retires the EF `CatalogDb` + the `CatalogModel` EF entity set from the active path (remaining deferred MS-SQL target records only in docs, no code).
  - Staged sub-steps: 3a (DI wiring — DONE, `ca52169`); 3b (service endpoints emit Contracts records via `ICatalogStore`); 4 (drop `CatalogDb` refs from `CatalogServiceClient`, remove `CatalogDb`); 5 (migrate WinUI/Testing consumers).
  - `CatalogServiceClient` no longer references `CatalogDb` and no `Microsoft.AspNetCore.OpenApi` (BL-7.2 acceptance).
- **Related:** ADR-0007 (catalog decoupling), ADR-0006 (interface-boundary / value records, seams only where a real second target exists), ADR-0002/0003 (governance/anti-drift).
