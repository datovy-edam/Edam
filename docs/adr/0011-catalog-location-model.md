# ADR-0011 — The Catalog is the location system: container + URI addressing

- **Status:** Accepted — direction (2026-09-18)
- **Context:** Locations are stated in many places, in several vocabularies: `appsettings.json` (`AppSettings:AssetConsolePath`, `AssetDataPath`, `AssetProjectsPath`, `DefaultInPath`, `DefaultOutPath`, `DefaultTextMapFolder`) **duplicated across ~13 project copies**; `Edam.Settings.json` (`App.ConsolePath`, `App.UriList[]`); per-container catalog settings (`Edam:Catalog:Target`, `ConnectionStrings:catalog`, `Edam:Catalog:FileSystemRoot`); and relative references inside `*.Args.json`. Values mix **absolute machine paths** (`C:\prjs\Datovy.Edam/…`, `C:\Users\esobr\Documents/…`), **CWD-relative** paths (`.\app-data/Edam.Studio/Edam.App.Data/`, `../../TextMaps/`), **empty strings with implicit fallbacks**, and mixed separators. "Is it absolute?" is decided by `path.IndexOf(':') == -1` (`ConfigurationHelper.GetAbsoluteAppDataPath`) and relative values resolve against `AppSettings.ApplicationDataFolder` = **MyDocuments** — which on the development machine is **OneDrive-redirected**. **ADR-0010** already moved the *packaged Studio host* off that path (sanitized MSIX seed + `LocalFolder` overlay) — but it decides only *where the host's data root is*, not *how a location is named*. ADR-0009 made the project surface provider-independent (`IProjectResources`, `ProjectPath`, no CWD), and the Catalog already models a container whose backing may be a file system, PostgreSQL or a REST service (`ContainerType`, `ContainerBinding{ContainerId,Target,BaseUri}`). The missing piece is a **single, storage-independent way to name a location**.
- **Decision:**
  1. **A location is an address, not a path.** An address is **container + path**, carried as one URI: `catalog://<container>/<path>`. The container is the URI authority; the path is the catalog path. The same address is valid whether the container is backed by a disk, a database or a service.
  2. **Locations are stated once per container, and only there.** The container registry (id, name, type, default flag) is the single declaration of where projects live; **all sub-paths are computed**, never configured.
  3. **Bindings are separate from locations.** *Where* a container's storage physically is (folder / DSN / service base URI) is one statement per container at machine/service level (configuration, environment or DI) — never a project location, never per project, never inside an artifact. `ContainerBinding{ContainerId,Target,BaseUri}` is that shape.
  4. **One vocabulary: the collection *is* the container** (ADR-0009). `Edam.Settings.json`'s `UriList[]` and `ProjectCollectionInfo` are the same concept and converge on the `ProjectCollectionInfo` record.
  5. **Well-known locations are named, not pathed.** The structure already encoded in `ProjectFolders` becomes addressable by name: `Projects/<name>/{Archive,Arguments,Documents,Files,UseCases,Samples,Libraries,TextMaps}`, plus app-level `Templates`, `TextMaps`, `Samples`, `Temp`. Short aliases (`project:documents`, `app:templates`) expand against the default container; they are **sugar, never the storage of record**.
  6. **Relative references resolve against the referring artifact's address** — not the CWD, not a configured root. `./Archive/x.xsd` inside `…/Projects/<name>/Arguments/x.Args.json` means `…/Projects/<name>/Archive/x.xsd` **in the same container**. The `*.Args.json` format is unchanged (ADR-0009).
  7. **Physical paths are ephemeral and derived.** A real path appears only where bytes must be touched locally — the runner's working folder: materialize from `IProjectResources`, run the by-path readers, capture artifacts back (PE-5a/5b). No configured location is ever a physical path.
  8. **Secrets are references.** A container may name a credential by key (`vault://catalog`); the value lives in the vault/environment, never in a committed settings file — and, per ADR-0010, never in the packaged seed.
  9. **Resolution happens once, is logged, and fails fast**, naming the address, the container and the resolved target. `Directory.SetCurrentDirectory` is never a resolution mechanism.
- **Options considered:**
  1. **Keep physical paths and document the conventions** — rejected: the "convention" *is* the defect; it is machine-specific, cannot express *which* container a path belongs to, and breaks the moment content moves into a catalog.
  2. **`(containerId, path)` as two fields everywhere** — rejected as the public form: two fields drift apart in transit (config, args, logs, signatures). A single address composes, validates and logs as one value (kept internally if convenient).
  3. **Path-only addressing with globally-unique catalog paths** (today: content keys are the item full path and containers are disambiguated by prefixing the container id into the path — `/<collectionId>/Projects/<name>`) — rejected as the model: it makes the container a *convention inside the path* only because content keys are not container-scoped, and it caused a real cross-container collision in PE-3.
  4. **A new settings file for locations while leaving today's keys alone** — rejected: two sources of truth; the legacy keys stay authoritative in code and drift.
  5. **Logical names only, no URIs** — rejected as canonical: they cannot address a non-default container or an app-level location; retained as aliases over addresses.
- **Consequences:**
  - *Positive:* one place states where projects live; **the same settings drive file-system and catalog containers** (the ADR-0009 goal); machine paths, CWD dependence and separator drift disappear; the shipped seed becomes **content to import** rather than a location config must reach (continuing ADR-0010's direction); "where did it look?" is answerable from one logged table; and carrying the container *in the address* removes cross-container path collisions structurally.
  - *Cost:* `IContentStore`/`IProjectResources` keys must become **container-scoped**, and the `/<collectionId>/` path prefix dropped — a provider change with migration implications for already-stored content; a resolver plus a **compatibility reader** must translate the legacy keys during transition; the 13 settings copies and the `AppSettings`/`ConfigurationHelper`/`AppData` path helpers must be retired; consumers (Studio bridge, args resolution, the deprecated static `Project` surface) must move to the resolver.
  - *Neutral:* the address shape is a contract in the sense of ADR-0008 — changing it later is breaking, so it is fixed here deliberately.
