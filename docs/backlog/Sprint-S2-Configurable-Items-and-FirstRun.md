# EDAM — Sprint S2 plan: configurable items & first-run setup

> **Status:** **Proposed next-sprint plan (2026-09-27) — not started; no code written.** Per `docs/backlog/README.md`, items live in files by ID; this file groups the work and its sequencing. **Authority:** approved requirements + AGENTS.md remain the current authority; this is a planning aid.

## Sprint S2 — "Ask once, explain, remember: unset configuration + a first-run that works"

**Primary goal:** make the values the application *cannot invent* resolvable **with the user in the loop** — informed, validated, asked once, and never guessed silently — and land the first instance of it: a **default project** offered as **`Edam.Sample`** (organization = **Edam**).

**Decisions this sprint implements (already made):** **ADR-0013** (unset configuration: registry, per-item policy, batched ask, user-state overlay, validation at ask, diagnostics audit) and **ADR-0012** (first-run default project: empty state first; a gated, one-time project created by the host through the existing seams; `Edam.Sample`; local binding only; never resurrecting after a delete; content shipped as seed content).

### Priority order

1. ✅ **CF-1 — Settings reader states `unset` / `set` / `invalid`** — **DONE 2026-09-27:** `ProjectSettings` now returns, for every item it looks at, a `ConfigurationItemInfo(Key, State, Value, Source, Problem)`. **`Presence` is what makes an item `Set`** — an empty string is a *stated* value, so it can never trigger a prompt; **resolution is unchanged** (the reader **states**, the host decides what to ask, ADR-0013 decisions 1 and 4). Sources are named (the item's own key · a translated legacy key · `EDAM_ROOT`), invalid values are **reported rather than thrown** (`PROVIDER_FAMILIES` vs `STORAGE_KINDS` are now explicit constants, and a `postgres`/`service` binding without a credential **name** is invalid), and a local binding with no location yet is **Unset (pending)** — the first-run case — not an error. **Verified:** new **`configuration (CF-1)` conformance group — ALL CONFORM (13 checks)**, whole suite green. **Two real defects the new checks caught and fixed:** a *translated* legacy value was reported `Unset` (presence was read from the item's own key instead of the legacy key), and an environment override reported the config value instead of the winning one. *Headless; done first — everything else depends on it.*
2. ✅ **CF-2 — The configurable-items registry** — **DONE 2026-09-27:** `ConfigurableItems` (in `Edam.Data.Projects.DependencyInjection`, beside the settings reader) is the **one definition per askable item**: `ConfigurableItemInfo(Id, Key, Title, WhatItIs, WhatItAffects, Policy, Default, Storage, Validate)`. First entries: the **starter project name** (`AskOnceWhenUnset`, default **`Edam.Sample`**, app-data overlay, validated) and the **once-per-installation marker** (`SilentDefault`, packaged settings — never asked). `ToAsk(config)` returns the **batch** to put in front of the user — unset askable items **plus** stated items their validator rejects — and `StateOf(config, item)` gives "invalid" **one** definition (the CF-1 states + the registry's validator), so a stated-but-unusable value is **reported, never replaced** (`Value` keeps what was stated). The **name rules** are implemented here as the first validator (ADR-0013 decision 7): letters/digits/`.`/`-`/`_` only — **no separator at all**, which is what makes leaving `/Projects` impossible — no leading/trailing dot or space, a 64-character cap, device names rejected, and `Projects`/`Templates`/`TextMaps`/`Samples`/`Temp` reserved. **Verified:** new **`registry (CF-2)` conformance group — ALL CONFORM (12 checks)**, whole suite green. *Headless.* **CF-5 becomes "reuse this validator in the dialog and the create path" rather than re-implementing the rules.**
3. ✅ **CF-3 — The user-state overlay** — **DONE 2026-09-27:** `IStateStore` (Read/Write/Remove-by-null/ReadAll + a reported `Location`), `FileStateStore` (the per-user app-data **overlay** `Edam.UserState.json` — created on demand, written atomically, and a missing/empty/**corrupt** file treated as "nothing stated" rather than fatal), `InMemoryStateStore`, and **`UserConfiguration`** — the answers: `Answer(item, value)` stores into the store the item's `Storage` names and **refuses** an answer its validator rejects (nothing lands on disk); `Effective` layers the overlay onto the base configuration, so an answer is ordinary configuration from then on; `ToAsk()` is the batch **after** the answers (so answering an item makes it stop being asked); `Reset()` forgets the answers but **not** the packaged marker, and `Reset(key)` forgets exactly one. **Verified:** new **`state (CF-3)` conformance group — ALL CONFORM (13 checks)**, whole suite green — including *"the answer makes the item STOP being asked"*, the refused-invalid-answer rule, the marker surviving a reset, durability across store instances, the corrupt-file rule, and the file being readable JSON. *Headless.* **The headless half of S2 is therefore complete (CF-1…CF-3); what remains is UI-facing (CF-4/CF-5, DP-1…DP-5) and needs the Studio.**
4. ✅ **CF-4 — One ask surface, generated from the registry** — **BUILT 2026-09-27 (build-verified; UI behaviour needs the user's F5):** **`ConfigurationPrompt.ShowIfNeededAsync(XamlRoot, UserConfiguration)`** renders the batch **from the registry** — no item is hardcoded: each ask shows the item's `Title`, *what this is* and *what it affects*, pre-fills the default, and **validates where the user answers** (an unusable answer keeps the dialog open with the reason and writes nothing); **Save** stores each answer in the store its policy names, **Later** changes nothing — every ask/answer/deferral goes to the **diagnostics panel**. **`PackagedStateStore`** is the WinUI `IStateStore` over `ApplicationData.Current.LocalSettings` (the marker; unavailable settings are never fatal, a failed write is logged). The Studio bridge exposes **`ProjectServicesHelper.UserConfiguration`** (appsettings + the app-data **overlay** at the app-data root + the packaged store), and **`MainWindow`** triggers the ask from the root content's **`Loaded`** event — the earliest moment a dialog can be shown — with `Activated` as a fallback, i.e. **after the shell is up**, never during `OnLaunched`, once, and reporting every outcome (including *"nothing to ask"*) to the diagnostics panel. *User-verified (F5).* **Threshold noted:** a dialog is right for a small batch; if the batch grows past ~4 items this becomes a first-run **page**.
5. **CF-5 — Name validation, reused in the dialog** — the path-safety rules from ADR-0013 decision 7 (character allow-list; no leading/trailing dot or space; reserved device names rejected; **no `.`/`..` segments**; length cap; case-insensitive uniqueness): a name must not be able to escape `/Projects`, and the New-Project dialog must reject one at entry. *Headless + UI.*
6. **DP-1 — Empty state in the project tree** — "no projects yet" plus a create action and a template choice. *Safe half: no writes, no gates. UI; user-verified.*
7. **DP-2 — Project delete / rename** — the **precondition** for creating anything on the user's behalf (creation is otherwise a one-way door). *UI; user-verified.*
8. **DP-3 — The gated, one-time default project** — offered as **`Edam.Sample`**; gates: asked/answered once (marker) · container **empty** · binding **local/file-system** · switch `Edam:Projects:CreateDefaultProject` (on for local, off otherwise); created through the **existing seams** (`IProjectStore` + `IProjectSeeder`, no special-casing); **never resurrects**; reports itself to the diagnostics panel. *Depends on CF-3/CF-4 and DP-2.*
9. **DP-4 — Content that can actually run** — ship a small sample input in the packaged seed and define the starter recipe (folders + starter arguments + input) as an address sequence, so the sample project is not structurally complete and inert. *Content + docs.*
10. **DP-5 — Verification** — the headless `default project` conformance group (creates exactly one when every gate holds; does nothing with a distinct reason per gate; never resurrects; addressable as `/Projects/<name>` with no path and no CWD; the seeded arguments resolve `./Files/…` inside the project) plus the Studio first-run check (user). *Headless + user.*

### Sequencing note

**CF-1 → CF-2 → CF-3** are headless and verifiable here; **CF-4, CF-5 (UI half), DP-1, DP-2** are UI and user-verified; **DP-3** must follow **DP-2** (no silent creation while there is no way out). Nothing in this sprint writes into the packaged seed at runtime.

### Sprint gates (Definition of Sprint-complete)

- Build **0 errors** across the affected solutions; the existing headless conformance suites stay green, plus the new `default project` group (and the CF checks) **ALL CONFORM**.
- The **first-run surface is skippable** and never blocks startup; deferring leaves a documented fallback and a diagnostic entry, never a silent guess.
- `unset` / `set-to-empty` / `invalid` are distinguished and reported distinctly; an item is asked **once** and never again; an invalid answer is rejected where it is entered.
- The default project is created **only** through the existing seams, is **never resurrected** after a delete, and is **not** created when the container is not empty or the binding is not local.
- ADR-0012 and ADR-0013 recorded; `docs/HANDOFF.md`, the backlog index, `Open-Decisions.md` and the Area CF/DP docs current.
- **D9** resolved (recorded) — name `Edam.Sample`, organization `Edam`, local-only gating, user-state overlay for answers, `LocalSettings` for the marker, delete-before-create, offer/ask rather than silent create.
